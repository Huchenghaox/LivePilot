# AI直播运营助手 PRD

## 1. 产品定位

AI直播运营助手面向普通主播和直播团队运营人员。用户上传抖音后台数据截图、直播录像或录音后，系统用 AI 输出直播复盘、问题原因、下一场动作、可直接念的话术、实时救场建议和合规提醒。

产品不是数据罗盘，不复制抖音后台，而是把直播数据转化成：

- 发生了什么；
- 依据是什么；
- 为什么发生；
- 下一场什么时候调整；
- 主播应该说什么；
- 用什么数据验证。

## 2. 核心原则

- 用户只做少量选择，AI 主动判断主播类型、问题标签和能力标签。
- 页面少，当前 MVP 主导航只保留四项：首页、开播准备、直播复盘、我的。
- 每页只有一个主要任务。
- 高级设置默认折叠。
- 首页不展示模型参数、Token、Prompt、工作流节点、数据库字段、OCR 置信度等技术信息。
- 一场复盘主报告只展示一个最大问题、两个次要问题、一个最值得保留的优势。
- 合规嵌入播前、复盘和实时助手，不单独做复杂系统。

## 3. 用户与场景

创建主播时只选择主要方向：

- 内容分享；
- 情感陪伴；
- 才艺娱乐；
- 商品或服务销售。

直播形式可勾选：

- 单人口播；
- 评论互动；
- 互动连麦；
- 商品或服务讲解。

更细标签由 AI 内部判断。

## 4. 当前 MVP 范围调整

当前优先目标收缩为“抖音后台截图复盘 MVP”。先暂停以下能力的继续开发和前台入口：

- 音视频上传；
- FFmpeg；
- ASR 语音转写；
- 说话人识别；
- 连麦分析；
- 实时助手；
- 悬浮提词；
- 高光剪辑；
- 动态背景；
- 自动场控。

已完成的基础代码保留，但不作为当前用户主流程入口。

当前核心闭环：

创建主播 → 新建直播复盘 → 上传多张抖音后台截图 → AI 自动识别截图类型和数据 → 用户确认或修改数据 → 选择报告模式 → 生成直播复盘 → 输出三个核心问题 → 生成下一场具体执行方案 → 保存历史记录 → 后续场次进行简单对比。

当前主导航只保留：

- 首页；
- 开播准备；
- 直播复盘；
- 我的。

第一版模型用途只保留：

- 图片识别；
- 文字分析。

当前模型策略：

- 文字分析模型与图片识别模型完全独立配置，可使用不同 Base URL、API Key 和模型名。
- 当前默认文字模型使用 `glm-5.1` 生成真实复盘报告。
- 当前暂无可用真实多模态图片模型，图片模型状态显示为未配置。
- 截图识别支持两种模式：
  - 开发演示模式：显式使用 Mock 图片识别，并提示“当前使用模拟识别结果，仅用于功能演示。”
  - 正式使用模式：未配置图片模型时提示用户手动录入关键数据，后续可配置视觉模型。
- Mock 结果不得伪装成真实识别结果。

## 5. Beta 主页面

2. 首页；
3. 主播档案；
4. 开播准备；

6. 数据确认；
7. 直播报告；
8. 我的设置；
9. 模型设置。

## 6. 首页

首页回答三个问题：

- 我下一步该做什么；
- 最近一场直播表现如何；
- 下一场需要改什么。

首页展示：

- 顶部主按钮：开始准备下一场直播、上传一场直播复盘；实时助手标记为后续开放或隐藏；
- 最近一场直播：直播日期、直播时长、综合结论、最大问题、下一场首要任务；
- 本周成长任务：最多三个动作、执行状态、改善情况。

## 7. 开播准备

采用四步向导：

1. 告诉 AI 今天播什么：选择主播、大致主题、预计时长、提升目标。
2. AI 生成开播方案：主题、标题、封面文案、结构、开场 3 分钟、互动节点、关注引导、风险提醒。
3. 生成完整直播稿：简洁提纲、分段话术、完整长稿；长稿按 15-20 分钟切段，每段有新用户承接、互动问题、内容小结、后续悬念。
4. 开播前检查：标题、封面、直播稿、话术风险、连麦规则、设备、目标；结果只显示可以开播、有建议调整、有严重风险。

标题、封面、静态背景都放在开播准备流程内，不做独立一级模块。

## 8. 合规风控

播前筛查覆盖：

- 极端判断、婚恋煽动、男女对立、群体攻击、人身攻击；
- 医疗和心理诊断、法律定性、政治敏感、未成年人；
- 色情低俗、暴力或自伤、隐私信息、诱导打赏、站外引流、虚假宣传、绝对化承诺。

展示结果：

- 需要修改；
- 建议修改；
- 暂未发现明显问题。

每个问题必须包含原句、简短风险说明、推荐改法、一键替换。

## 8.1 规则与运营提示中心

规则、治理方向和运营策略会持续变化，系统不把所有规则写死在代码或固定 Prompt 中。

当前 MVP 在“我的”页面下增加“规则与提示”入口，不新增一级导航。

规则类型只保留：

- 平台官方规则：来自官方公告、官方规则或官方课程，需要来源和发布时间，可信度最高。
- 运营经验：团队或主播总结，AI 输出时只能表述为“运营建议”“经验判断”。
- 主播个人提醒：某个主播收到的违规提示或需要避开的主题，只作用于指定主播。
- 系统提示：管理员添加的产品级提示，例如数据不足时不得推断具体话术问题。

规则流程：

- 人工录入规则；
- AI 理解并结构化；
- 人工确认；
- 规则生效；
- 报告生成时筛选相关有效规则；
- 报告展示规则依据和来源类型；
- 停用或过期规则不再进入新报告。

报告中引用规则必须区分来源，禁止把运营经验写成“抖音明确规定”。

## 9. 直播复盘

五步上传向导：

1. 选择主播，默认最近使用的主播。
2. 上传抖音后台截图，可多张，AI 自动判断截图类型。
3. 当前 MVP 暂不开放音视频上传，补充资料入口后续开放。
4. 确认 AI 识别数据，只展示关键指标并允许直接修改。
5. 选择报告方式：直接告诉我怎么改、给我专业分析、两种都要。

关键指标包括：直播时长、累计观看、最高在线、平均在线、新增关注、评论数、点赞数、平均停留、流量来源。

## 10. 复盘报告

第一屏先显示：

- 一句话总结；
- 本场最大问题；
- 本场最大优势；
- 下一场最重要的三个动作。

三个核心问题卡片包含：

- 问题是什么；
- 数据证据；
- 可能原因；
- 下一场怎么改；
- 推荐话术；
- 验证指标。

下一场方案至少包含：

- 推荐主题；
- 5 条标题；
- 开场 3 分钟；
- 3 个互动节点；
- 2 个关注引导；
- 1 条新流量承接话术；
- 下一场三个目标。

数据详情折叠展示流量、停留、互动、关注、用户画像、内容表现、连麦表现、风险表现。

报告页提供生成下一场主题、标题、完整直播稿、加入成长任务和继续问 AI。

报告生成策略：

- 先运行可解释规则诊断，再调用文字模型生成报告。
- 同时检索当前有效的规则与运营提示，只传入与主播、直播形式、主题、违规提示相关的规则。
- 报告必须区分数据事实、指标对比、AI 推断、可能原因和需要主播补充的信息。
- 只有截图数据时，不得编造具体分钟、具体话术、具体冷场节点、具体连麦问题或精确因果关系。
- 保存前进行质量检查，避免空泛建议、结果保证、引用不存在数据和缺少验证指标。
- 每份报告保存使用的模型名称、Prompt 版本和规则版本快照。

## 11. 实时助手

当前 MVP 暂停实时助手前台入口，后续开放。

Beta 只保留三个区域：

- 提词内容：字号、滚动速度、暂停、上一段、下一段、语速跟随。
- AI 当前建议：一次只显示一条。
- 快捷救场：冷场了、来新流量了、评论少了、需要引导关注、连麦接不住、出现敏感内容。

实时助手只给建议和话术，不自动操作抖音账号。

## 12. 模型配置

普通用户看到简单模式：

- 使用平台模型；
- 使用自己的模型。

自定义模式放在高级设置：

- API 地址；
- API Key；
- 模型名称；
- 模型用途：文字分析、图片识别。

所有模型调用通过统一适配层。API Key 后端加密或预留加密层，前端脱敏，不写日志，支持测试连接和删除。

## 13. 分期

Phase 1：基础闭环，完成登录、邀请码、主播档案、模型配置、新建直播、截图上传、图片识别、数据确认、简单复盘、三个核心问题、下一场任务、历史记录。

Phase 2：内容分析，完成视频/音频上传、FFmpeg 音频提取、语音转写、内容分析、话术风险、内容型报告、综合报告、完整直播稿。当前 MVP 暂停继续推进 Phase 2，优先把截图复盘闭环打磨完成。

Phase 3：播前准备，完成主题、标题、直播稿、合规筛查、封面、静态背景、开播检查。

Phase 4：实时助手，完成浏览器麦克风、实时转写、网页提词、语速跟随、快捷救场、基础风险提醒。

Phase 5：高光切片，完成高光识别、FFmpeg 切片、字幕、标题、话题、9:16 导出。
